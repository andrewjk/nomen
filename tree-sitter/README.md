# tree-sitter-nomen

A [tree-sitter](https://tree-sitter.github.io/) grammar for the
[Nomen](../README.md) programming language, for syntax highlighting and
structural editing in Neovim, Helix, Zed and other tree-sitter editors.

The VS Code extension and the website keep using the TextMate grammar; this
grammar is not wired into either.

## Layout

| Path                               | What it is                                                             |
| ---------------------------------- | ---------------------------------------------------------------------- |
| `grammar.js`                       | The grammar                                                            |
| `src/scanner.c`                    | External scanner: nested comments, `#raw` bodies, strings, generic `<` |
| `src/parser.c`, `src/*`            | Generated by `tree-sitter generate` (committed, as is conventional)    |
| `queries/highlights.scm`           | Syntax highlighting                                                    |
| `queries/injections.scm`           | C / assembly inside `#raw { … }` blocks                                |
| `queries/locals.scm`               | Scopes, definitions and references                                     |
| `queries/folds.scm`                | Folding                                                                |
| `queries/indents.scm`              | Indentation (nvim-treesitter conventions)                              |
| `test/corpus/`                     | `tree-sitter test` cases, one or more per construct                    |
| `scripts/parse-all.mjs`            | Parses every `.nm` file and README/SPEC code block in the repo         |
| `scripts/build-editor-queries.mjs` | Derives the Helix and Zed query sets from `queries/`                   |
| `editors/helix/`                   | Helix `languages.toml` snippet and runtime queries                     |
| `editors/zed/`                     | A Zed extension (install as a dev extension)                           |

## Development

The tree-sitter CLI is a local devDependency (no global install needed):

```bash
cd tree-sitter
npm install
npx tree-sitter generate   # regenerate src/ after editing grammar.js
npx tree-sitter test       # run the corpus tests
npm run parse-all          # parse core/, demos/, bench/, README.md and SPEC.md
npm run build-queries      # regenerate editors/*/ queries after editing queries/
```

`parse-all` reports every input with an `ERROR` or `MISSING` node, and warns
about "value statements" (a bare `x` or `a + b` as a statement), which are
legal grammar but never real Nomen — they usually mean a declaration or a
multi-line expression was split in the wrong place. Inputs that are expected
not to parse can be listed in the script's `KNOWN_GAPS` (currently none).

`queries/` follows nvim-treesitter conventions and is the source of truth.
The Helix and Zed copies under `editors/` are generated from it (Helix with
its own capture names and the highlight patterns reversed, because Helix
gives the first matching pattern precedence where Neovim and Zed take the
last); `npm run build-queries -- --check` fails when they are stale. The
editors' `indents.scm`, Zed's `brackets.scm`/`outline.scm`/`config.toml` and
the Helix `languages.toml` are hand-written.

After changing the grammar, run `npx tree-sitter test --update` to refresh
expected trees, and review the diff.

### How the grammar handles Nomen's trickier corners

- **Newlines.** Nomen has no statement terminators, so newlines are mostly
  whitespace. The exceptions mirror the compiler: a `(`, `[` or `-` at the
  start of a line begins a new statement instead of calling, indexing or
  subtracting from the previous line, and `return` only takes a value on the
  same line. Binary operators other than `-` (and `.` member access) still
  continue across a line break.
- **Generic `<`.** `List<int>()` versus `a < b` is decided by the scanner: a
  `<` opens type arguments when it touches the preceding name and a matching
  `>` follows on the same line with only type-ish characters between. Code
  formatted with `nomen format` always fits this.
- **Strings.** Content, `\{…}` interpolation (with `:spec` format specs) and
  multi-line strings are structured nodes. A line break inside a string
  continues it when the next line starts with `"`, and otherwise ends it —
  the same rule as the compiler's tokenizer.
- **`#raw { … }`.** The body is one `raw_body` node, ended by the first `}`
  outside C/asm strings and comments (the compiler's
  `src/raw_block.ts` scan). `#raw("c")` bodies are injected as C; unmarked
  bodies inside an `#if META.arch == "c"` / `"aarch64"` arm (or `#switch`
  case) are injected as C or `asm`.
- **Comptime names.** `get_#{field.name}`, `#{field.name}_count` and
  `S_#{w.name}` parse as `template_name` nodes with `splice` children;
  `#self`, `#init`, `#i` are `hash_identifier`s.

## Editor setup

The grammar lives in a subdirectory of the Nomen repository, so editors point
at `https://github.com/andrewjk/nomen` with `tree-sitter` as the
location/subpath. Every editor also needs to know that `.nm` files are Nomen.

### Neovim (nvim-treesitter)

Register the parser before nvim-treesitter installs parsers (for example in
your `init.lua`):

```lua
vim.filetype.add({ extension = { nm = "nomen" } })

local parser_config = require("nvim-treesitter.parsers").get_parser_configs()
parser_config.nomen = {
  install_info = {
    url = "https://github.com/andrewjk/nomen",
    location = "tree-sitter",
    files = { "src/parser.c", "src/scanner.c" },
    branch = "main",
  },
  filetype = "nomen",
}
```

Then run `:TSInstall nomen`. nvim-treesitter does not ship queries for
custom parsers: copy (or symlink) this folder's `queries/*.scm` into
`queries/nomen/` somewhere on your `runtimepath`, e.g.
`~/.config/nvim/queries/nomen/`.

On the nvim-treesitter `main` branch (the rewrite), register the parser from
a `User TSUpdate` autocommand instead:

```lua
vim.api.nvim_create_autocmd("User", {
  pattern = "TSUpdate",
  callback = function()
    require("nvim-treesitter.parsers").nomen = {
      install_info = {
        url = "https://github.com/andrewjk/nomen",
        location = "tree-sitter",
        queries = "tree-sitter/queries",
      },
    }
  end,
})
```

For `#raw` blocks to highlight, also install the `c` and `asm` parsers.

### Helix

Append [`editors/helix/languages.toml`](editors/helix/languages.toml) to
`~/.config/helix/languages.toml`, then fetch and build the grammar and copy
the queries into Helix's runtime:

```bash
hx --grammar fetch
hx --grammar build
mkdir -p ~/.config/helix/runtime/queries
cp -r editors/helix/queries/nomen ~/.config/helix/runtime/queries/
```

Pin the grammar's `rev` to a commit hash for reproducible builds.

### Zed

[`editors/zed/`](editors/zed/) is a complete extension: run **zed: install
dev extension** and pick that folder. Its `extension.toml` pins the grammar
to a commit of this repository; bump `rev` to pick up grammar changes.

## Known limitations

- `a<b` written without spaces and followed by a `>` later on the same line
  (with nothing but names, commas and brackets between) is read as type
  arguments. `nomen format` spaces binary operators, so formatted code is
  unaffected.
